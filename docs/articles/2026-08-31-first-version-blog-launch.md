你好，欢迎来到「小羊嚣张」的博客。

今天想先写一篇简单的开站文章，作为这个博客的第一句话：博客第一版终于上线了。

它还不是一个内容非常丰富、每个细节都打磨完美的网站，但它已经有了一个可以访问、可以写文章、可以交流，也可以慢慢成长起来的空间。对我来说，这比一直停留在“等准备好了再开始”更重要。

## 为什么想做一个博客

做博客的想法其实并不复杂。我希望有一个属于自己的地方，把平时遇到的问题、学习过程中的理解、做项目时留下的思考，以及一些生活里的小片段记录下来。

这些内容未必每一篇都成熟，也未必都能马上给别人带来帮助，但写下来之后，它们就不只是转瞬即逝的想法，而会变成以后可以回头查看的记录。

我也希望这里不是一个只展示最终结果的地方。一个功能是怎么开始的，中间遇到了什么问题，哪些方案没有生效，最后为什么选择现在的实现，这些过程同样值得留下来。很多时候，真正有价值的经验并不在“最后成功了”，而在于走过的那段弯路。

所以，这个博客更像是一个持续建设中的个人空间：一边写，一边整理，一边把它做得更好。

## 第一版已经有什么

目前博客主要分成几个部分：

- 首页：展示最新文章、站点信息和一些内容入口。
- 文章页：支持 Markdown 正文、目录、相关文章和评论互动。
- 归档、分类与标签：方便按照时间、主题和关键词浏览内容。
- 动态：记录一些比正式文章更轻量的日常更新。
- 友链：收集值得访问的网站和朋友们的博客。
- 留言：如果你有想交流的内容，可以在这里留下消息。

除了内容页面，第一版也保留了一些基础体验：日间与夜间主题切换、响应式布局、文章搜索、评论回复、表情和图片上传，以及背景视频在不同设备上的适配。

这些功能并不是为了让页面看起来复杂，而是希望访问、阅读和交流的过程尽量自然一些。博客的核心仍然是内容，功能只是让内容更容易被找到、读完和留下反馈。

## 这个博客是怎么搭起来的

前台使用 Nuxt 4、Vue 3 和 TypeScript 构建，通过 Nuxt SSR 输出页面。这样做的一个重要原因，是希望文章内容不仅能在浏览器端加载，也能更好地兼顾首屏展示和搜索引擎阅读。

数据和管理部分是独立的服务：后端使用 Go、Gin、GORM 和 PostgreSQL，管理端负责文章、分类、标签、评论、动态以及站点配置等内容。前台通过 API 获取这些数据，因此以后更换页面样式时，不需要重新设计整套内容数据。

部署方面，第一版也把流程整理成了 GitHub Actions 和阿里云 ECS 的自动发布：代码推送后自动安装依赖、构建生产文件、上传到服务器，再由 systemd 启动服务并执行健康检查。每个版本使用独立的 release 目录，发布失败时可以切回上一版本。

这套流程听起来比“把文件传上去”多了几步，但它让我更清楚每一次发布对应哪一个提交，也让我敢于继续修改网站，而不用担心一次失败就只能手忙脚乱地恢复。

## 第一版还有很多不完整的地方

第一版的意义不是宣布“博客已经完成”，而是承认它终于开始运行了。

现在的文章数量还不多，部分页面和交互仍然会继续调整，样式细节、移动端体验、内容组织和部署流程也都有改进空间。某些想法可能会被保留，某些想法也可能在实际使用后被删掉或重做。

我觉得这很正常。一个个人博客不需要一开始就拥有最终形态，它更适合在真实使用中慢慢形成自己的风格。先把第一版上线，再根据阅读、写作和交流过程中遇到的问题持续迭代，可能比闭门打磨一个“看起来完整”的版本更有意义。

## 接下来想继续做什么

接下来会优先做几件事：

1. 持续补充真正有内容的文章，把做项目时的过程和经验整理出来。
2. 继续优化文章阅读体验，包括排版、目录、图片和移动端适配。
3. 完善搜索、评论、留言和友链等互动功能。
4. 记录博客自身的建设过程，包括技术选择、问题排查和发布维护。
5. 保持自动部署和版本回滚流程可用，让每次更新都更容易验证和恢复。

这些事情没有严格的截止日期。博客是一个长期项目，重要的是不要只停留在规划里，而是持续写一点、改一点、发布一点。

## 写在第一篇文章最后

如果你是第一次来到这里，感谢你愿意花一点时间看看这个刚刚上线的博客。

这里以后可能会有前端、后端、部署、工具使用，也会有一些不那么技术化的记录。内容不一定始终保持同一种形式，但我希望它们都尽量诚实：做过的事情好好写，没做过的事情不夸大，遇到的问题也不刻意藏起来。

如果你发现页面有问题，或者对某篇文章有想法，欢迎通过评论或留言告诉我。每一条反馈，都会让这个刚搭起来的空间更接近它应该有的样子。

第一版上线不是终点，更像是正式开始记录的一个起点。

以后，就在这里见。
